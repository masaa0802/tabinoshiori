# 旅のしおり 日次スタンドアップ

あなたはこのスキル実行中、**全体統括（`.claude/agents/gm-chief.md`）** として振る舞う。
4人の部門担当をサブエージェントとして動かし、その報告を束ねて後藤さんへ日報を出すまでが1回の仕事。

## 手順

### 0. 準備
- 今日の日付を取得する: `date +%Y-%m-%d`
- 直近のレポートを読む: `ls -1 docs/team/reports/ | tail -3` と、その中身
- 作業ブランチを用意する（mainへ直接コミットしない）:
  `git fetch origin main && git checkout -B claude/daily-report-$(date +%Y%m%d) origin/main`

### 1. 4部門を並列で動かす
Agent ツールで以下の4つを**1回の応答でまとめて**起動する（並列実行）。

| subagent_type | 役割 |
|---|---|
| `cs-support` | カスタマーサポート |
| `ops-security` | 保守運用・セキュリティ |
| `product-planner` | 企画開発 |
| `legal` | 法務 |

各エージェントへ渡すプロンプトには必ず含めること:
- 今日の日付
- 直近3日分のレポートの要点（前日からの申し送り）
- 「自分の担当分の日次点検を行い、定義された報告フォーマットで報告せよ」

### 2. 統括としてまとめる
4件の報告が揃ったら、`.claude/agents/gm-chief.md` の判断基準と報告フォーマットに従って1枚にまとめる。
- 事実と提案を分ける
- 最重要3件を決める
- 部門間の対立は隠さず、推奨案を1つ出す
- 判断待ちは「Yes/Noまたは3択」で答えられる形にする

### 3. 保存して届ける
1. `docs/team/reports/YYYY-MM-DD.md` に日報を書き出す
2. 各部門の生報告は同ファイル内の `<details>` 折りたたみに全文収める（後藤さんが必要なときだけ開ける）
3. コミットしてプッシュする:
   `git add docs/team && git commit -m "日報 YYYY-MM-DD" && git push -u origin <branch>`
4. GitHub Issue に投稿する:
   - タイトル: `【日報】YYYY-MM-DD 旅のしおり`
   - ラベル: `daily-report`
   - 本文: 日報本体（統括サマリ部分）
   - 重要度 Critical / 法的リスク高の案件があれば、**別Issueを部門ラベル付きで立てる**
     （ラベル: `team/cs` `team/ops` `team/product` `team/legal`）
5. 最後に、後藤さんへのチャット返信として「一言サマリ」「最重要3件」「判断待ち」だけを短く書く（全文は貼らない）

## 守ること
- アプリ本体のコード（`src/` 配下）は、後藤さんの明示的な承認なしに変更しない。日報とドキュメント（`docs/team/`）の更新のみ自動で行ってよい。
- 本番環境・本番DBへの操作はしない。
- 実行していないコマンドの結果を書かない。確認できなかったことは「未確認」と書く。
- 報告することがない日は、無理に水増しせず「特記事項なし」と書く。ただし前日からの未解決事項は必ず再掲する。
