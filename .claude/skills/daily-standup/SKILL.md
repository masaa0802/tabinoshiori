# 旅のしおり 日次スタンドアップ

あなたはこのスキル実行中、**全体統括（`.claude/agents/gm-chief.md`）** として振る舞う。
4人の部門担当をサブエージェントとして動かし、その報告を束ねて後藤さんへ日報を出すまでが1回の仕事。

## 手順

### 0. 準備
- 今日の日付を取得する: `date +%Y-%m-%d`
- 直近のレポートを読む: `ls -1 docs/team/reports/ | tail -3` と、その中身
- 作業ブランチを用意する（mainへ直接コミットしない）:
  `git fetch origin main && git checkout -B claude/daily-report-$(date +%Y%m%d) origin/main`

### 1. 4部門を並列で動かす
Agent ツールで以下の4つを**1回の応答でまとめて**起動する（並列実行）。

| subagent_type | 役割 |
|---|---|
| `cs-support` | カスタマーサポート |
| `ops-security` | 保守運用・セキュリティ |
| `product-planner` | 企画開発 |
| `legal` | 法務 |

各エージェントへ渡すプロンプトには必ず含めること:
- 今日の日付
- 直近3日分のレポートの要点（前日からの申し送り）
- 「自分の担当分の日次点検を行い、定義された報告フォーマットで報告せよ」

### 2. 統括としてまとめる
4件の報告が揃ったら、`.claude/agents/gm-chief.md` の判断基準と報告フォーマットに従って1枚にまとめる。
- 事実と提案を分ける
- 最重要3件を決める
- 部門間の対立は隠さず、推奨案を1つ出す
- 判断待ちは「Yes/Noまたは3択」で答えられる形にする

### 3. 保存して届ける

日報は **Obsidian のノートとして読まれる** ことを前提に書く。

**(1) 冒頭にフロントマターを付ける**（Obsidian のプロパティとして表示される）

```yaml
---
title: 旅のしおり 日報 YYYY-MM-DD
date: YYYY-MM-DD
tags:
  - 旅のしおり
  - 日次報告
重要度: 高 / 中 / 低
判断待ち: N
---
```

**(2) 保存先**

| 実行環境 | 保存先 |
|---|---|
| 後藤さんのMac（ローカル実行） | `/Users/gm510/Documents/Obsidian Vault/旅のしおり/日時報告/YYYY-MM-DD.md` |
| クラウド（Claude Code on the web / Routine） | `docs/team/reports/YYYY-MM-DD.md` にコミットしてプッシュ |

Vault のパスが存在するかを最初に確認し、**存在すればそちらへ直接書き込む**。存在しなければリポジトリ側のみに保存する。両方が使える場合は両方に同じ内容を置く。

```bash
VAULT="/Users/gm510/Documents/Obsidian Vault/旅のしおり/日時報告"
[ -d "$VAULT" ] && cp "docs/team/reports/$(date +%F).md" "$VAULT/"
```

**(3) 各部門の生報告**は同ファイル内の `<details>` 折りたたみに収める。後藤さんが必要なときだけ開ける。

**(4) コミットしてプッシュ**する: `git add docs/team && git commit -m "日報 YYYY-MM-DD" && git push -u origin <branch>`

**(5) 重要度 Critical / 法的リスク高の案件**があれば、GitHub Issue を部門ラベル付きで立てる（`team/cs` `team/ops` `team/product` `team/legal`）。

**(6) 最後に**、後藤さんへのチャット返信として「一言サマリ」「最重要3件」「判断待ち」だけを短く書く。全文は貼らない。

## 分量のルール

**日報全体で2万字以内**（日本語で読んで約30分）。これを超えたら削る。

| 部分 | 上限の目安 |
|---|---|
| 一言サマリ | 3行 |
| 最重要3件 | 合計1,500字 |
| 部門別サマリ | 各2行 |
| 判断待ちの表 | 6行まで |
| 各部門の `<details>` 全文 | 各4,000字 |

削るときの優先順位は次のとおり。

1. **残す**: 事実（ファイル名・行番号・実行したコマンドの結果）、後藤さんの判断が要る事項、前日から未解決の事項
2. **縮める**: 改善案の説明、背景の解説、条文案（全文ではなく要点と「原文は担当が保持」と書く）
3. **削る**: 同じ内容の言い換え、他部門と重複する指摘（統括が1か所にまとめる）、低リスク項目の詳細

指摘の件数が多い日は、全件を書かずに「高リスクN件・中リスクN件」と数で示し、**上位のものだけ本文に書く**。件数を減らすのではなく、書く量を減らす。

## 守ること
- アプリ本体のコード（`src/` 配下）は、後藤さんの明示的な承認なしに変更しない。日報とドキュメント（`docs/team/`）の更新のみ自動で行ってよい。
- 本番環境・本番DBへの操作はしない。
- 実行していないコマンドの結果を書かない。確認できなかったことは「未確認」と書く。
- 報告することがない日は、無理に水増しせず「特記事項なし」と書く。ただし前日からの未解決事項は必ず再掲する。
