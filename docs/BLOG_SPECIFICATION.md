## 1. 概要・目的

### プロダクトビジョン
「**たびのまえに**」は、旅行の前につまずくところを一つずつ減らすメディア。

旅行に行きたい気持ちはあるのに踏み出せない人は多い。理由は行き先が決まらないことより、
「いくらかかるか読めない」「何を準備すればいいか分からない」「現地で困りそう」といった
**具体的な不安**であることが多い。その不安を一つずつ潰すことを目的とする。

読者は旅のしおりのユーザーに限らない。**これから旅行に行くすべての人**に向けて書く。
記事は製品を知らない読者が読んで完結する内容にし、しおりは「調べたことを形にする手段」
として、読み終わったあとに自然に差し出す。

### この位置づけにした理由
当初は「しおり作成の質を上げるための情報インフラ」として構想していたが、
それだと読者が既存ユーザーに限られ、新規の検索流入を取りこぼす。
不安の解消を主題にすることで、まだ製品を知らない層にも届く。

なお、しおり作成中のユーザーを支える役割も引き続き持つ（2-2参照）。
両方を兼ねるが、**優先するのは前者**。

### 名前について
`BLOG_NAME`（`src/lib/site.ts`）に定義してある。
ここを書き換えるとヘッダー・フッター・RSS・構造化データに一括で反映される。
URL は `/blog` のままなので、名前を変えても SEO 上のコストは無い。

### 運営方針
- **記事作成者**: 運営のみ（microCMS から入稿）
- **公開形態**: 全記事一般公開（SEO最優先）
- **更新頻度目標**: 週1〜2記事（立ち上げ期）
- **事実に基づくこと**: 推測や伝聞の数字は載せない。確認できたことだけを、
  確認元とセットで書く（3-3参照）

## 2. ビジネス要件

### 2-1. 集客（SEO・AI検索）
旅行の不安に関する検索から流入を取り、読み終わった読者にしおりを差し出す。

```
「旅行 いくらかかる」「ESTA いつまでに」などで検索
  → 不安に答える記事に流入（この時点では製品を知らない）
  → 記事を読んで不安が減る
  → 末尾のCTA「この内容をもとに、旅程を組み立てる」
  → グループ作成・しおり作成
```

**CTAは読者の便益で書くこと。** 「しおりに反映できます」のような製品を知っている前提の
文言は、検索から来た初見の読者に通じない。

**ターゲットキーワード例**

不安の種類（タグ）に対応させる。

| 不安の種類 | キーワード例 |
|---|---|
| お金の不安 | 「航空券 安い時期」「旅行 予算 目安」「◯◯ 旅行 費用」 |
| 手続きの不安 | 「ESTA 申請 いつまで」「パスポート 残存期間」「海外旅行保険 必要か」 |
| 現地の不安 | 「◯◯空港 市内 行き方」「海外 SIM おすすめ」「◯◯ 両替 どこで」 |
| 段取りの不安 | 「◯◯ 何日必要」「旅行 スケジュール 立て方」「◯◯ モデルコース」 |

AI検索（ChatGPT・Perplexity等）からの流入も狙う。
主要なAIクローラーを `robots.ts` で明示的に許可し、一覧ページの構造化データに
全記事の絶対URLを列挙して、記事単体を直接たどれるようにしている（8章）。

### 2-2. ユーザーリテンション
しおり作成中のユーザーにも、目的地に応じた記事を届ける。

- 情報タブの末尾に、旅程の目的地と一致する記事を最大3件表示（実装済み）
- 記事内のスポットをワンタップでしおりに追加（**未実装**。7-1・7-2）

**しおり作成フローを妨げないこと。** 導線は以下の3箇所に限定し、
スマホ下部ナビへのタブ追加はしない（4分割を維持する）。

| 位置 | 意図 |
|---|---|
| LP の CTAセクション直下 | ヒーローCTAより下に置き、作成導線に干渉させない |
| LP フッター | 全ページ共通の受け皿 |
| しおり「情報」タブ末尾 | 予約情報の保管場所であり主動線ではないため |

### 2-3. 収益化
- **広告枠**: LP と記事ページに Google AdSense を設置済み。
  読み始めた読者を追い出す配置にしないこと。記事ページは次の2箇所だけに置く

  | 位置 | 条件 | 広告ユニットの環境変数 |
  |---|---|---|
  | 本文の途中（2つ目の見出しの直前） | 見出し（h2）が3つ以上ある記事のみ | `NEXT_PUBLIC_ADSENSE_SLOT_ARTICLE_MID` |
  | 記事末尾（旅程作成CTAの後、関連記事の前） | 全記事 | `NEXT_PUBLIC_ADSENSE_SLOT_ARTICLE_BOTTOM` |

  - タイトル直下・本文の冒頭には置かない。読み始める前に広告で押し下げないため
  - 読了計測（`ReadTracker`）と旅程作成CTAの間には置かない。CTAへの導線と競合させないため
  - 下書きのプレビューには出さない
  - 広告ユニットIDが未設定の位置には広告を出さない（LP の FAQ 用ユニットでは代用しない）。
    環境変数を入れた位置から掲載が始まる。位置ごとにユニットを分けておくと、
    AdSense の管理画面でどちらが稼いでいるかを比べられる
- **アフィリエイト**: 宿泊・交通・ツアーの予約リンクを記事内に埋め込む。
  不安を解消する流れの中で自然に置けるため相性は良いが、
  収益目的で不要なリンクを増やすとコンセプトが崩れる
- **タイアップ記事**: 旅行関連企業との PR 記事（記事内でタグ表示）

いずれも、読者の不安を減らすという主題を損なわない範囲で行う。

### 2-4. ブランド構築
「旅行前の不安に、事実で答えてくれるメディア」という評価を積み上げる。

金額や相場のように鮮度が落ちる情報こそ、出典と調査時点を明示して扱う（3-3）。
これは読者の信頼に直結し、他の旅行メディアとの差別化にもなる。

## 3. コンテンツ戦略

### 3-1. 記事の分類（2軸）

読者が「自分の困りごと」からも「記事の種類」からも辿れるようにする。
2つの軸は直交しており、1記事は両方を持つ。

**軸1: 不安の種類（タグ）** — 読者の入口

| タグ | 潰す不安 | 記事例 |
|---|---|---|
| お金の不安 | 高そう・予算が読めない | 航空券が安くなる時期、格安で行く手段、予算の立て方 |
| 手続きの不安 | 何を準備すればいいか分からない | パスポート、ビザ・ESTA、保険、持ち物 |
| 現地の不安 | 言葉・移動・治安が心配 | 空港から市街への行き方、SIM・Wi-Fi、両替 |
| 段取りの不安 | 日程が組めない | モデルコース、何日必要か、詰め込みすぎない組み方 |

定義は `src/lib/microcms/tags.ts`。一覧ページ・sitemap・ナビはこの配列から自動生成される。
microCMS 側は `tags`（セレクトフィールド・複数選択）で運用する。選択式にしているのは、
テキスト入力だと打ち間違えたときに警告も出ないまま一覧から消えてしまうため。

**増減するときは `ANXIETY_TAGS` と microCMS の選択肢の両方を揃えること。**
片方だけ変えると、一覧ページはあるのに選べない（または選べるのに一覧に出ない）
状態になる。

一覧ページを持たない表示専用のタグは、別フィールドの `freeTags` に入れる。

**軸2: 情報の種類（カテゴリ）** — 記事の形式

| カテゴリ | 内容 | 優先度 |
|---|---|---|
| 旅の準備 | 出発前に決めること・そろえるもの | 最高 |
| 目的地ガイド | 行き先ごとの基本情報と現地での動き方 | 高 |
| モデルコース | 日数別の回り方の例 | 中 |

カテゴリは microCMS の `categories` API で管理する。追加・変更は管理画面で行える。

### 3-2. 記事の構成方針

- **読者は製品を知らない前提で書く**。しおりの説明を本文に混ぜない
- **一次情報・確認済みの情報を重視**。推測で書かない
- **不安に対する答えを先に出す**。背景の説明を長く置かない
- **スポットを紹介する記事には `spots` を紐づける**。将来のしおり追加機能で使う
- **末尾に CTA を置く**。位置は読了後で正しい。文言だけ読者の便益で書く

### 3-3. 金額・相場の扱い

**金額は出す。ただし注釈と根拠を必ず添える。**

数字を避けると読者の知りたいことに答えられない。一方、放置すると誤情報になる。
そこで運用ルールに頼らず、仕組みで担保している。

| 仕組み | 実体 | 効果 |
|---|---|---|
| 記事単位の注釈 | `PriceDisclosure.tsx` | `priceCheckedAt` を入れると冒頭に調査時点と出典が出る |
| 棚卸しの可視化 | `format.ts` の `isPriceStale()` | 調査から6か月でバナーが警告色になり「要更新」バッジが付く |
| 金額単位の注釈 | `PriceNote.tsx` / `PriceFigure` 型 | 出典と調査時点が**必須プロパティ**。注釈なしでは書けない |
| 根拠画像 | `PriceFigure.image` | 検索結果のスクリーンショット等を金額の直下に置ける |

入稿時は `priceCheckedAt`（日付）と `priceSources`（出典）を必ず設定する。
定期的に見直して `priceCheckedAt` を更新すること。

**棚卸しの運用（誰がいつ見直すか）は未定。** 仕組みは入っているが、担当と頻度は決めていない。

### 3-4. 立ち上げコンテンツ計画
| フェーズ | 本数 | 内容 |
|---|---|---|
| ローンチ時 | 10記事 | 4つの不安タグを均等に埋める。人気目的地（管理画面の統計から上位）を優先 |
| 〜3ヶ月 | +20記事 | モデルコース・目的地別の現地ガイド |
| 〜6ヶ月 | +30記事 | 長尾キーワード狙い |

立ち上げの10記事は、**どのタグにも記事が無い状態を作らない**ことを優先する。
タグ一覧が空だと、その不安を抱えた読者を取りこぼす。

## 4. システム設計

### 4-1. アーキテクチャ

```
microCMS（記事入稿・管理／SaaS）
  ├─ articles / categories / spots … リスト形式のAPIを3つ
  └─ 画像は images.microcms-assets.io から配信
        │
        │ microcms-js-sdk（GET のみ。書き込み権限は不要）
        │ 環境変数が未設定ならローカルのシードデータにフォールバック
        ▼
src/lib/microcms/   ← server-only。APIキーはここから外に出ない
  client.ts    SDK初期化・エンドポイント名の定義
  queries.ts   記事取得。CMSの切り替えはこのファイル内で完結する
  mappers.ts   microCMSレスポンス → BlogPost 型への変換
  types.ts     型定義
  format.ts    読了時間・日付・画像URL・料金の鮮度判定
               （クライアントからも読むので server-only にしない）
  jsonLd.ts    構造化データ生成
  tags.ts      「不安の種類」タグの定義
        │
        ├─ Server Component から直接呼ぶ（すべて SSG + ISR 1時間）
        │    /blog                  記事一覧
        │    /blog/[slug]           記事詳細
        │    /blog/category/[slug]  カテゴリ別一覧（情報の種類）
        │    /blog/tag/[slug]       タグ別一覧（不安の種類）
        │    /blog/feed.xml         RSS
        │    /sitemap.xml  /robots.txt
        │    LPの <BlogHighlights />
        │
        └─ Client Component からは Route Handler 経由（直接importは不可）
             /api/blog/related
               └─ しおり「情報」タブの <RelatedArticles />

microCMS webhook（任意。Hobbyプランでは利用できない）
  └─ /api/revalidate  HMAC-SHA256で署名検証 → 該当ページを再生成
```

**しおり連携（Hasura）について**

現状、ブログから Hasura への書き込みは無い。
情報タブの関連記事は、Hasura から取得したしおりの `destination` を
`RelatedArticles` に渡し、`/api/blog/related` で該当記事を引いているだけ。

7章の「記事内のスポットをワンタップでしおりに追加」（`activities` テーブルへの
書き込み）は**未実装**。`Spot` の型・スキーマ・表示用の `SpotCard.tsx` までは
用意してあるが、追加ボタンと旅程選択モーダルは作っていない。

### 4-2. レンダリング戦略
| ページ | 方式 | 理由 |
|---|---|---|
| 記事詳細 | ISR（revalidate: 3600） | SEO最優先・更新頻度が低い |
| 記事一覧 | ISR（revalidate: 3600） | 同上 |
| カテゴリ一覧 | ISR（revalidate: 3600） | 同上 |
| タグ一覧 | ISR（revalidate: 3600） | 同上 |
| 情報タブの関連記事 | Client Component + Route Handler | server-only のため直接取得できない |

`export const revalidate = 3600;` はリテラルで書くこと。
定数を import して代入すると `Invalid segment configuration export detected` で
ビルドが落ちる。

### 4-3. キャッシュ戦略
- 基本は ISR。記事の更新は最大1時間で反映される
- microCMS の webhook で `/api/revalidate` を叩くと即時反映できる。
  ただし **Hobby プランでは webhook を使えない**ため、その場合は ISR のみ。
  すぐ反映したいときはホスティング管理画面から手動で再デプロイする
- microCMS はプランごとにAPIリクエスト数の上限がある。
  `getAllPosts` / `getAllCategories` / `getPostBySlug` は React の `cache()` で
  包んであり、1ページの描画中に何度呼んでも通信は1回で済む

### 4-4. 下書きプレビューについて

**未実装。** microCMS には下書きプレビュー用の API がある（`draftKey` を付けて取得）が、
プレビュー用のルートは作っていない。必要になったら追加する。

## 5. microCMSコンテンツモデル

> エンドポイント名は `articles` / `categories` / `spots`。
> `src/lib/microcms/client.ts` の `MICROCMS_ENDPOINTS` と一致している必要がある。
> 3つともリスト形式で作成すること（形式は後から変更できない）。
>
> 実際に管理画面へインポートできるスキーマJSONを `microcms/schemas/` に置いてある。
> 以下の表は、そのJSONの内容を読みやすくしたもの。

### 5-1. articles（記事）

**URLスラッグは microCMS のコンテンツID。** 専用の `slug` フィールドは無い。
記事URLは `/blog/<コンテンツID>` になるため、記事作成時に「コンテンツIDを変更」から
英数字のIDを設定する運用にすること。自動生成のランダムIDだと読みにくいURLになり、
後から変えると URL が変わる。

`publishedAt` / `updatedAt` は microCMS のシステムフィールドなので定義不要。

| フィールド | microCMSの種類 | 必須 | 説明 |
|---|---|---|---|
| title | テキストフィールド | ✓ | 記事タイトル |
| excerpt | テキストエリア | ✓ | 一覧・OGPで使う抜粋（120文字以内が目安） |
| coverImage | 画像 | ✓ | アイキャッチ画像 |
| body | リッチエディタ | ✓ | 本文。HTML文字列として取得される |
| category | コンテンツ参照 → categories | ✓ | カテゴリ（情報の種類） |
| tags | セレクト（複数選択） | | 不安タグ。**1つ以上選ぶ**（3-1参照） |
| freeTags | テキストフィールド | | **カンマ区切り**。表示専用で一覧ページを持たない |
| destination | テキストフィールド | | **カンマ区切り**。しおりの目的地と突き合わせる |
| spots | 複数コンテンツ参照 → spots | | 記事内で紹介するスポット |
| souvenirs | 複数コンテンツ参照 → souvenirs | | お土産ガイドに並べる品（6-4）。並び順がそのまま表示順 |
| seoTitle | テキストフィールド | | 未設定なら title を使用 |
| seoDescription | テキストエリア | | 160文字以内。未設定なら excerpt を使用 |
| ogImage | 画像 | | 未設定なら coverImage を使用 |
| featured | 真偽値 | | ブログトップの大きな枠に表示 |
| priceCheckedAt | 日付 | | **金額を書いたら必須**。冒頭の注釈バナーに使う（3-3参照） |
| priceSources | テキストフィールド | | 同上。カンマ区切りの出典 |

`freeTags` と `destination` がカンマ区切りテキストなのは、microCMS に文字列配列型が
無いため。`mappers.ts` の `splitList()` がカンマ・読点・改行で分割する。

`tags`（セレクト）と `freeTags`（テキスト）は、`mappers.ts` の `toTagList()` が
`BlogPost.tags` の1本の配列にまとめる。アプリ側はこの1本だけを見ればよく、
不安タグか自由タグかの判別は `tags.ts` の `ANXIETY_TAGS` との完全一致で行う。

**スキーマインポート後に手動設定が2箇所必要。** スキーマJSONでは参照先APIを
指定できないため、`category` → `categories`、`spots` → `spots` を管理画面で設定する。

### 5-2. categories（カテゴリ）
| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| name | Short text | ✓ | カテゴリ名（例: 目的地ガイド） |
| slug | Short text | ✓ | URL用スラッグ |
| description | Short text | | カテゴリの説明 |
| order | Integer | | 表示順 |

### 5-3. spots（スポット）
記事内で紹介する場所。現在は `SpotCard.tsx` での表示と地図リンクに使っている。
将来の「しおりに追加」機能（7-1）のデータソースにもなる。

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| name | Short text | ✓ | スポット名 |
| description | Short text | ✓ | 簡単な説明（しおり追加時に表示） |
| placeId | Short text | | Google Maps Place ID |
| lat | Number | | 緯度 |
| lng | Number | | 経度 |
| address | Short text | | 住所 |
| activityType | Short text | | アクティビティ種別（観光・グルメ・宿泊など） |
| photo | Media | | スポット写真 |

### 5-4. souvenirs（お土産）
お土産ガイド（6-4）の1品。スキーマは `microcms/schemas/souvenirs.json`。

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| name | Short text | ✓ | 品名 |
| genre | Short text | ✓ | ジャンル。記事内の見出しと目次になる（例: お菓子 / お茶・食品 / 雑貨） |
| price | Short text | ✓ | 表示用の価格（例: 10個入り 約1,500円） |
| comment | Long text | | ひとこと |
| place | Short text | ✓ | 買える場所（店名・エリア）。地図リンクの検索語にもなる |
| address | Short text | | 住所。入れると地図リンクが正確になる |
| placeId | Short text | | Google Maps Place ID |
| availableInJapan | Boolean | | 日本でも買えるか。オフなら「現地でしか買えない」 |
| japanUrl | Short text | | 日本で買えるお店のURL。入れるとボタンが出る |
| sponsored | Boolean | | `japanUrl` が広告リンクか。オンで「PR」表記と `rel="sponsored"` |
| checkedAt | Date | ✓ | 価格・販売場所の確認日。6か月を過ぎると「要確認」 |
| photo | Media | | 正方形に切り抜いて表示。未設定ならジャンルごとの色の枠 |

## 6. ページ・機能仕様

### 6-1. ブログトップ（/blog）

**表示内容**
- イントロ: メディアの主旨を1〜2文で
- **気になっていることから探す**: 不安タグ4つ（読者の入口。カテゴリより上に置く）
- **記事の種類から探す**: カテゴリ
- 注目記事: `featured` の記事を大きく表示。無ければ最新記事
- 新着記事: カード表示
- CTA

未実装: カテゴリ別ピックアップ、目的地タグクラウド。記事数が増えてから検討する。

**カード表示項目**
- アイキャッチ画像（未設定ならグラデーションのプレースホルダ）
- カテゴリバッジ
- タイトル
- 抜粋
- 公開日
- 読了時間（本文の文字数から自動計算。日本語500字/分）

### 6-2. 記事一覧

2種類ある。どちらも新着順で、全件表示。

| パス | 軸 | 内容 |
|---|---|---|
| `/blog/category/[slug]` | 情報の種類 | カテゴリ別。カテゴリ切り替えナビ付き |

未実装: ページネーション、目的地タグフィルター。記事数が増えてから検討する。

### 6-3. 記事詳細（/blog/[slug]）

**ページ構成**
```
┌─────────────────────────────────────┐
│  パンくずリスト                       │
│  カテゴリバッジ                       │
│  タイトル                            │
│  不安タグ（一覧ページへのリンク）      │
│  公開日 / 更新日 / 読了時間           │
│  アイキャッチ画像                     │
│  抜粋                                │
├─────────────────────────────────────┤
│  料金の注釈バナー                     │
│  （priceCheckedAt がある記事のみ。     │
│    6か月経過で警告色）                │
├─────────────────────────────────────┤
│  本文                                │
│                                     │
│  ┌──────────────────────────────┐   │
│  │ 金額ブロック（PriceNote）      │   │
│  │ 金額・条件・根拠画像           │   │
│  │ 出典 / 調査時点（必須）        │   │
│  └──────────────────────────────┘   │
├─────────────────────────────────────┤
│  お土産ガイド（6-4）                  │
│  （souvenirs を紐づけた記事のみ）      │
├─────────────────────────────────────┤
│  この記事で紹介したスポット            │
│  （地図リンクまで。しおり追加は未実装） │
├─────────────────────────────────────┤
│  タグ一覧                            │
│  （不安タグはリンク、自由タグは表示のみ）│
├─────────────────────────────────────┤
│  CTA                                 │
├─────────────────────────────────────┤
│  あわせて読みたい                     │
│  （同目的地 → 同カテゴリの順で最大3件） │
└─────────────────────────────────────┘
```

**CTA（Call to Action）**

記事末尾に固定。**製品を知らない読者に通じる言い回しにすること。**

現在の文言は「この内容をもとに、旅程を組み立てる」で、続けて行き先と日程を入れると
何ができるかを説明している。「しおりに反映できます」のような、読者が製品を知っている
前提の書き方はしない。

未実装: モバイルのスクロール追従バナー。スポット追加機能が無いため保留している。

### 6-4. お土産ガイド（記事内）

記事に `souvenirs` を紐づけると、本文の直後にジャンル別の一覧が出る
（`SouvenirGuide.tsx`）。本文は導入として短めに書く。カテゴリは問わないが、
専用カテゴリ「お土産ガイド」（slug: `souvenir`）を想定している。

ねらいは「日本でも買えるか」「どこで買えるか」「いつ時点の情報か」が
1品ごとにすぐ分かること。見た目は他の部品（`SpotCard` など）と揃え、
色はエメラルドとグレーだけを使う。お土産専用の配色は持たせない。

```
┌─────────────────────────────────────┐
│  7品を紹介・うち現地限定 5品           │
│  最終確認 ◯年◯月◯日                   │
│  (お菓子 3) (お茶・食品 2) (雑貨 2)    │
├─────────────────────────────────────┤
│  お菓子 3品                           │
│  ───────────────────────────────    │
│  ┌──────┬────────────────────────┐  │
│  │ 写真 │ 品名 [現地限定]          │  │
│  │      │ 価格                     │  │
│  │      │ ひとこと                 │  │
│  │      │ 📍買える場所  ◯年◯月◯日時点│  │
│  │      │ 日本で買えるお店を見る PR │  │
│  └──────┴────────────────────────┘  │
└─────────────────────────────────────┘
```

- 1列のリスト。写真はカードの端まで広げ、余白は写真と文字の間だけ
  - スマホ: 写真を上に全幅（4:3）、その下に文字
  - `sm` 以上: 写真を左に幅176pxで置き、カードの高さに合わせて伸ばす
- 「日本でも買えるか」は品名の横のラベルで出す。現地限定はエメラルド、日本でも買えるものはグレー
- ジャンルの並びは、紐づけた品の中で最初に出てきた順。目次はジャンルが2つ以上のときだけ出す
- 確認日は品ごとに必須。冒頭の「最終確認」はその最新値。6か月を過ぎた品には「要確認」
- 広告リンクは `sponsored` をオンにする。オフのまま広告リンクを置くとステマ規制に触れる

## 9. 技術仕様

### 9-1. 使用パッケージ
| パッケージ | 用途 |
|---|---|
| `microcms-js-sdk` | microCMS の API クライアント |
| `server-only` | APIキーがクライアントバンドルに載るのを防ぐマーカー |

リッチテキスト用のライブラリは使っていない。microCMS のリッチエディタは HTML 文字列を
返すため、`HtmlBody.tsx` が `dangerouslySetInnerHTML` で描画している。
`@tailwindcss/typography` も導入していないので、本文のスタイルは子要素セレクタで当てている。

> `HtmlBody.tsx` はサニタイズしていない。入稿者が運営のみである前提（2章）。
> 外部ライターに入稿権限を渡す場合はサニタイズ処理の追加が必須。

### 9-2. 環境変数
| 変数名 | 必須 | 説明 |
|---|---|---|
| `MICROCMS_SERVICE_DOMAIN` | 必須 | サービスID。管理画面URL `https://<ここ>.microcms.io` の部分 |
| `MICROCMS_API_KEY` | 必須 | APIキー。GET 権限のみで足りる |
| `MICROCMS_WEBHOOK_SECRET` | 任意 | webhook 署名検証用。microCMS が発行するものではなく自分で決める値 |
| `NEXT_PUBLIC_BASE_URL` | 任意 | 未設定なら `https://tabinoshiori.jp` にフォールバック |

必須2つが未設定のあいだは `src/data/blogPosts.ts` のシードデータで動作し、
サーバーログに警告が出る。設定はソースコードではなくホスティングの管理画面で行う。
手順は `docs/MICROCMS_SETUP.md` を参照。

### 9-4. microCMSクライアント
```typescript
// src/lib/microcms/client.ts
import "server-only";
import { createClient } from "microcms-js-sdk";

export const MICROCMS_ENDPOINTS = {
  articles: "articles",
  categories: "categories",
  spots: "spots",
} as const;

const serviceDomain = process.env.MICROCMS_SERVICE_DOMAIN;
const apiKey = process.env.MICROCMS_API_KEY;

export const isMicroCMSConfigured = Boolean(serviceDomain && apiKey);

export const microcmsClient = isMicroCMSConfigured
  ? createClient({ serviceDomain: serviceDomain as string, apiKey: apiKey as string })
  : null;
```

**`server-only` を外さないこと。** クライアントコンポーネントから記事を取得する場合は
`/api/blog/related` のような Route Handler を経由する。直接 import するとビルドが落ちる。

### 9-5. ISR + Webhook構成
```
記事を公開・更新（microCMS）
  └─ Webhookを発火（Hobbyプランでは使えない）
       └─ /api/revalidate（Next.js Route Handler）
            ├─ X-MICROCMS-Signature を HMAC-SHA256 で検証
            │    不一致・欠落は 401
            └─ revalidatePath('/blog')
               revalidatePath('/')
               revalidatePath('/sitemap.xml')
               revalidatePath(`/blog/${contentId}`)
```

webhook を使わない場合は ISR のみで、最大1時間で反映される。

## 付録: microCMS セットアップ手順

手順の詳細は **`docs/MICROCMS_SETUP.md`** にある。概要は以下のとおり。

1. [microcms.io](https://microcms.io) でサービスを作成
2. `articles` / `categories` / `spots` をリスト形式で作成し、
   `microcms/schemas/*.json` からスキーマをインポート
3. `articles` の参照フィールド（`category` → categories、`spots` → spots）を
   管理画面で手動設定する。スキーマJSONでは参照先を指定できないため
4. サービス設定 → APIキー から GET 権限のキーを取得
5. ホスティングの環境変数に `MICROCMS_SERVICE_DOMAIN` と `MICROCMS_API_KEY` を
   設定して再デプロイ
6. （任意）Webhook を登録。Hobby プランでは利用できない
