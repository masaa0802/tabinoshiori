# ブログの効果測定と改善

記事の質を上げ続けるための仕組み。**何を測り、どう判断し、何を直すか**をここに書く。

前提として、ブログの目的は旅のしおりのユーザーを増やすこと。
ページビューが増えても旅程が作られなければ意味がない。
だから「読まれたか」ではなく「**旅程作成につながったか**」を軸に見る。

---

## 1. 4段階で測る

どこで落ちているかが分からないと打ち手が決まらない。段階に分けて測る。

| 段階 | 指標 | どこで見るか |
|---|---|---|
| 1. 検索で見つかる | 表示回数・CTR・掲載順位 | Search Console |
| 2. 読まれる | 読了率 | GA4 `blog_article_read` ÷ ページビュー |
| 3. CTAを押す | CTAクリック率 | GA4 `blog_cta_click` ÷ ページビュー |
| 4. 旅程を作る | **記事別の旅程作成数** | GA4 `itinerary_created`（`source_article` 別） |

4が最終的な成果。1〜3はそこへ至る途中経過で、**どこが詰まっているかの切り分け**に使う。

---

## 2. 送っているイベント

実装は `src/lib/blog-analytics.ts`。

| イベント名 | いつ | パラメータ |
|---|---|---|
| `blog_article_read` | 本文の末尾が画面に入ったとき（1記事1回） | `article_slug` / `article_category` / `reading_minutes` |
| `blog_cta_click` | 旅程作成CTAを押したとき | `article_slug` / `article_category` / `cta_position` |
| `blog_related_click` | しおりの情報タブから記事へ移動したとき | `from` / `to_slug` |
| `itinerary_created` | 旅程が作られたとき | `source`（`blog` / `direct`）/ `source_article` / `source_category` / `source_cta_position` |

### 記事と成果の紐付け方

CTAを押した時点で、記事の slug を `sessionStorage` に記録する。
旅程が作られたときにそれを読み、`itinerary_created` に付けて送る。

- **1時間で期限切れ**にしている。何日も前に読んだ記事が誤って紐づかないように
- 使ったら消す。同じセッションで2つ目の旅程を作っても二重計上しない
- タブを閉じれば消える（`sessionStorage` のため）

**この紐付けだけが「記事が役に立ったか」を示す。** 壊すと改善の根拠がなくなるので、
`/group/new` の作成処理を触るときは `trackEvent("itinerary_created", ...)` を消さないこと。

### `cta_position` の値

| 値 | 場所 | 記事と紐づくか |
|---|---|---|
| `article_footer` | 記事末尾のCTA | **紐づく** |
| `header` | ブログ共通ヘッダー | 紐づかない（記事を特定できないため） |
| `blog_top` | ブログトップのCTA | 紐づかない |

記事別の評価に使えるのは `article_footer` だけ。
ヘッダーからの流入は「ブログ全体の貢献」として別に見る。

## 3. GA4 側の設定（管理画面での作業）

**イベントを送るだけでは記事別に見られない。** カスタムディメンションの登録が要る。

### 3-1. カスタムディメンションを登録する

GA4 → 管理 → カスタム定義 → カスタムディメンションを作成

| ディメンション名 | 範囲 | イベントパラメータ |
|---|---|---|
| 記事slug | イベント | `article_slug` |
| 記事カテゴリ | イベント | `article_category` |
| CTA位置 | イベント | `cta_position` |
| 流入元記事 | イベント | `source_article` |
| 流入元 | イベント | `source` |

**登録した時点以降のデータにしか適用されない。遡及しない。**
記事を書き始める前に設定すること。

保存後は**範囲とイベントパラメータを変更できない**。パラメータ名は1文字でも違うと
永久にデータが入らず、作り直しになる。上の表からコピーして貼ること。

イベントパラメータの入力欄は、まだ一度も送信されていないパラメータを候補に出さない。
その場合は手で打ち込めば「"article_slug" を使用」のような選択肢が出る。

### 3-2. キーイベント（コンバージョン）に設定する

GA4 → 管理 → イベント → **「最近のイベント」タブ** → `itinerary_created` の行で
「キーイベントとしてマークを付ける」をオンにする。

**先に一度イベントを発生させる必要がある。** GA4 は受信したことのあるイベントしか
一覧に出さず、イベント名を手入力でキーイベントに追加するボタンは無い
（2026-10-05 時点で確認）。本番でブログ記事 → CTA → 旅程作成まで通しでやると出てくる。
反映まで最大24時間かかる。

最初に開いたとき「キーイベント」タブが表示されているが、ここは**すでに印が付いた
ものだけ**の一覧。「最近のイベント」タブに切り替えること。

> 「イベントを作成」ボタンは使わない。既存のイベントから別のイベントを合成する機能で、
> すでにコードから送っている `itinerary_created` には不要。使うと二重になる。

**キーイベントの設定が遅れてもデータは失われない。** イベント自体は実装した時点から
記録されており、後からマークを付ければ過去の分も集計される。
カスタムディメンション（3-1）と違って遡及する点が異なる。

### 3-2-1. 計測が動いているかを確かめる

GA4 → 管理 → **DebugView**。Chrome拡張「Google Analytics Debugger」を入れて
オンにした状態でブログを操作すると、イベントがリアルタイムで流れる。

イベントをクリックするとパラメータの中身まで見えるので、`article_slug` に
記事のslugが入っているかをここで確認する。反映を待たずに検証できる唯一の方法。

### 3-3. 探索レポートを1つ作る

GA4 → 探索 → 空白

| | |
|---|---|
| 行 | 流入元記事（`source_article`） |
| 値 | イベント数 |
| フィルタ | イベント名 = `itinerary_created` |

**記事別の旅程作成数**が出る。月次レビューで最初に見るのはこれ。

### 3-4. Search Console と連携する

GA4 → 管理 → Search Console のリンク設定。
検索での表示回数・CTRが GA4 側でも見られるようになる。

## 4. Search Console の設定

コードでは完結しない。手作業が要る。

1. `https://tabinoshiori.jp/sitemap.xml` を送信
2. 主要記事のインデックス登録をリクエスト
3. 公開から**2週間ほどはデータが出ない**。焦って記事を書き直さないこと

## 5. 月次レビューの手順

毎月1回、30分を目安に。記事が10本を超えたら始める。

### 手順

1. **GA4の探索レポート**（3-3）で、記事別の旅程作成数を見る
2. **Search Console**で、記事別の表示回数・CTR・掲載順位を見る
3. 下の表に当てはめて、直す記事を**2本だけ**選ぶ

### 判断の基準

| 症状 | 原因 | 打ち手 |
|---|---|---|
| 表示回数が少ない | 検索需要とズレている / 順位が低い | 題材を見直す。記事を増やすより既存記事を厚くする |
| 表示回数はあるがCTRが低い | タイトル・ディスクリプションが弱い | `seoTitle` と `seoDescription` を書き直す |
| 読まれるが読了率が低い | 冒頭で期待とズレている / 構成が悪い | 冒頭200文字を書き直す。見出しを整理する |
| 読了率は高いがCTAが押されない | CTAの文言・位置 / 記事と製品の接点が薄い | CTA直前に「この続きは旅程に落とせる」という橋渡しを足す |
| CTAは押されるが旅程が作られない | `/group/new` の入力が重い | 記事ではなくフォーム側の問題。別途対応 |

**一度に直すのは2本まで。** 何を変えたから良くなったのかが分からなくなる。

### 直したら記録する

`docs/team/reports/` に、何をどう直したかと、翌月どうなったかを残す。
記録がないと同じ試行錯誤を繰り返す。

## 6. 記事を公開するときのSEOチェック

入稿時に毎回確認する。

- [ ] `seoTitle` は32文字以内。**検索されたい語を前半に**入れる
- [ ] `seoDescription` は120文字以内。記事を読むと何が分かるかを書く
- [ ] `excerpt` は一覧とOGPに出る。120文字以内
- [ ] `coverImage` を設定した（未設定でもOG画像は自動生成されるが、実写のほうが強い）
- [ ] 不安タグを1つ以上選んだ
- [ ] `destination` を入れた（しおりの目的地と突き合わせて関連記事に出る）
- [ ] 金額を書いたなら `priceCheckedAt` と `priceSources` を設定した
- [ ] 他の記事へのリンクを本文中に1つ以上入れた（回遊とクロールの両方に効く）

### 自動で入るもの（確認不要）

- `canonical` / OGP / Twitter Card
- 構造化データ（Article / BreadcrumbList / Blog / ItemList）
- sitemap への追加、RSS への掲載
- アイキャッチ未設定時のOG画像（`opengraph-image.tsx` が生成）

---

## 7. やらないこと

- **記事数を増やすことを目標にしない。** 旅程作成につながらない記事を量産しても、
  サイト全体の評価を下げるだけ
- **順位を毎日見ない。** 変動が大きく、判断を誤る。月次で十分
- **根拠のない数字を書かない。** 金額・相場は調べた日と出典を添える（`docs/BLOG_HANDOVER.md` 参照）
